# 0.4.0 contract: kolay kurulum / easy setup

**Status:** binding from 2026-11-08 (manager). The scope is the owner's, and so are the decisions
quoted below. Tracking issue: #234.

**Kısaca (TR):** 0.4.0'ın amacı, ARCILOGGER'ın uzman gerektirmeden kurulup ilk ayarlarının
yapılabilmesi:
- PostgreSQL kurulumla gelir; ayrıca kurulmaz.
- Kurulum soruları pencerelerde sorulur.
- Zaman damgası varsayılan olarak TÜRKTRUST'tır.
- Kurulum sonunda otomatik bir denetim çalışır.
- Günlük damga testi sayısı tarayıcıdan ayarlanır.
- Yedek klasörü tarayıcıdan seçilir.
- E-posta sayfasında hazır sağlayıcı seçimi bulunur.

E-posta bağlantısı yalnızca kullanıcı adı ve parolayla kurulur; OAuth yoktur. Wave 6 bu sürümün
parçası değildir.

## 0. Rules and decisions

### 0.1 Owner decisions (2026-11-08, quoted)

- "Önerim: bir sonraki sürüm (0.4.0) 'kolay kurulum' olsun" — approved.
- "şuan benim imza uygulamam sadece türk trust kalsın ve mümkünse kök sertifika içinde gömülü
  olsun." The root was built in by 0.3.1; 0.4.0 makes TÜRKTRUST the default.
- "bunları 0.4.0 versyonda ekleyelim": the e-mail provider presets.
- "maalesef apppassword yok. mümkünse tümü sadece kullanıcı adları ve şifreleri ile bağlansınlar
  … 0.4.0 versyona başla". Hence:
  - OAuth is out;
  - every preset connects with a user name and password, or without a login for a relay that
    authorises by IP.

### 0.2 Rules that bind every package

The product rules of `CLAUDE.md` hold unchanged. In particular:
- no "legally compliant" claim;
- raw logs untouched;
- no secret in the repository, logs, command lines or answers;
- TR first with EN beside it;
- every API error carries `code`, `message_tr` and `message_en`;
- bound SQL parameters only;
- no invented facts about third parties (each one is in §0.5 with a test).

In addition, for 0.4.0:
- **Existing installations keep working unchanged on upgrade.**
  - An upgrade keeps the configured time-stamp provider, the existing PostgreSQL service, the
    policy file and the backup folder.
  - Only a **new** installation gets the new defaults.
- **No setup step runs a console-script launcher** (`venv\Scripts\arcilogger-*.exe`). It runs
  `python.exe -P -m <module>` (0.3.3; Windows application control blocks the launchers).
  - New PowerShell code goes through `Invoke-ArciProcess` / `Invoke-ArciExe`.
  - New Inno Setup code never starts a launcher.
- **Third-party binaries are never committed.** The release build downloads them with a pinned
  SHA-256 (`components.json`), and the bundle's `SHA256SUMS` covers them.

## 2. Design

### 2.1 P1 — Bundled PostgreSQL

#### 2.1.1 Build

- `components.json` gets `postgresql_binaries` (`role: bundled`) with these fields:
  - `version` (the 16.x minor);
  - `url`;
  - `sha256`;
  - `layout` (S1);
  - `licence` (PostgreSQL License, with its file).
- `Build-ArciBundle.ps1` downloads the zip when the bundle has no copy, verifies the SHA-256 and
  unpacks it into `bundle\postgresql\`.
- The bundle's `SHA256SUMS` and the SBOM list the component.
- **First pin:** the manager runs the release job once with `-ComponentUrl` and records the
  resulting SHA-256 in `components.json`, with `sha256_source` stating how it was obtained and
  the date.
- The bundle's `THIRD-PARTY-NOTICES.txt` carries the PostgreSQL licence.
- The existing `postgresql` (operator, EDB installer) entry stays for servers that bring their own.

#### 2.1.2 Install (new server, no PostgreSQL 16 service)

The new step is `postgres.install`, between the preflight and `database.prepare`. It is skipped
when a `postgresql-x64-16` service exists. It does the following:
1. **Binaries:** copies the binaries to `C:\Program Files\ARCILOGGER-PostgreSQL\16\`. This is a
   separate folder because the program folder is swapped on upgrade.
2. **Data folder:** `<data root>\pgdata`, on the data drive the installer already chose.
3. **Superuser password:** generated with `New-ArciRandomPassword -Length 32` and stored as secret
   `postgres.superuser` through `secret set` on stdin. It is never on a command line, in the log or
   in the plan.
4. **initdb:** `initdb -D <pgdata> -U postgres -A scram-sha-256 --pwfile=<temp file> -E UTF8
   --locale=C`.
   - The temp file is created with an ACL for the current user only and deleted in `finally`.
   - Encoding and locale are those of the CI database; P1 checks them against the CI service
     definition and records them.
5. **`postgresql.conf`:**
   - `listen_addresses = 'localhost'`;
   - `port = 5432`; when 5432 is taken, the step stops with code 2 and a message naming the owner
     of the port;
   - nothing else is changed.
6. **Service:** `pg_ctl register -N postgresql-x64-16 -D <pgdata> -S auto -U
   "NT AUTHORITY\NetworkService"`.
   - The ACL plan gets an entry: NetworkService has modify rights on `<pgdata>` and nothing else.
   - The service is started.
7. **Record:** `install\state.json` gets `postgres: {bundled: true, version, bin, data}`.

The rest of the database steps run as today. They connect as `postgres` with the stored password
instead of asking for it.

#### 2.1.3 Upgrade, rollback, removal

- **Upgrade:** a bundled instance whose bundle carries a newer 16.x minor gets its binaries
  swapped. Order: stop the service, rename the binaries folder to `.previous`, copy the new one,
  start, and verify with `psql -c "select version()"`. On failure the previous binaries come back.
  No major change.
- **Rollback (`-Rollback`):** leaves PostgreSQL as it is.
- **Removal without data:** keeps PostgreSQL and its data.
- **Removal with data (`-RemoveData`):** for a bundled instance it also removes the service, the
  binaries and `<pgdata>`. It reads `postgres.superuser` from the secret store before the store is
  deleted. For an operator instance it behaves as today (drops ARCILOGGER's database and role
  only).

#### 2.1.4 Texts

- The Inno message `RunInstaller` loses "ve PostgreSQL parolası" when the bundled path is taken.
  Setup knows this before the window opens: it checks whether the service exists.
- New TR/EN lines for the step and its refusals (port taken, binaries missing, initdb failed),
  each with what to do.

### 2.2 P2 — Setup pages and the TÜRKTRUST default

- **Inno pages:** `ARCILOGGER.iss` adds two custom pages, shown only when `BundleIsInstalled` finds
  no installation (a first install).
  - **Page 1 "Kurum bilgileri / Organisation":**
    - Kuruluş adı (required, 2–120 characters);
    - Saat sunucusu (optional: host name or IPv4);
    - Yönetici bilgisayarının adresi (required: IPv4 or IPv4/CIDR, comma separated).
  - **Page 2 "Zaman damgası / Time stamping":** radio buttons
    - "TÜRKTRUST (önerilen)" — default;
    - "Kamu SM (Zamane; Java ve Zamane istemcisi gerekir)".
  - **Validation in the pages:** shape only (empty, length, characters). The PowerShell preflight
    keeps the full checks. A value it refuses stops with code 2 before any change, and the Inno
    error dialog names the field.
  - **Passing the values:** `-SiteName`, `-NtpServer`, `-AdminAddress`, and the new
    `-TimeStampProvider turktrust|zamane` (default `turktrust`). Each value is quoted as a single
    argument. They are not secrets.
- **Example configuration:** `arcilogger.example.toml` `[tsa]` becomes the TÜRKTRUST block:

  ```toml
  provider = "turktrust"
  url = "https://zd.turktrust.com.tr/"
  roots_dir = "C:/ProgramData/ARCILOGGER/kamusm-roots"
  legal_root_fingerprints = []   # H7 is built in for TÜRKTRUST
  ```

  - With `-TimeStampProvider zamane`, setup writes today's Kamu SM keys (`provider`, `url`, `port`,
    `java`, `zamane_jar`, `zamane_verify_flag`).
  - An existing `arcilogger.toml` is never rewritten (upgrade).
- **Installer next steps:** the TÜRKTRUST text of 0.3.1 becomes the default.
- **Web:** Ayarlar → Zaman damgası, when the server reports neither provider in use (`mock`):
  - it offers TÜRKTRUST first and Kamu SM second;
  - the order of the server choices puts the TÜRKTRUST ones first;
  - an existing Kamu SM site is unchanged.

### 2.3 P3 — Self-test

`arcilogger-core --config <toml> selftest [--json]` prints the rows below and exits 0 (all ok or
skip), 1 (a warn) or 2 (a fail). `--json` prints
`{"rows":[{"id","status","message_tr","message_en"}]}`.

| id | ok when | status otherwise |
|---|---|---|
| `config` | the configuration loads | fail |
| `secrets` | the secret store opens, and the secrets the configuration needs are stored | fail |
| `database` | a connection works and the schema is at the head | fail |
| `roots` | at least one root is installed and, for TÜRKTRUST, H7 is among them | fail |
| `tsa.reach` | TÜRKTRUST: an HTTPS request to `url` without credentials gets any HTTP answer within the timeout (401 is expected, S6). Kamu SM: a TCP connection to host:port. Mock: skip | warn |
| `smtp` | SMTP disabled: skip. Enabled: connect, TLS as configured, EHLO and, with a user name, AUTH; then QUIT. Nothing is sent | warn |
| `clock` | the existing clock check is within its limit | warn |

- **Messages:** fixed TR/EN texts in `core/src/arcilogger_core/selftest.py`.
  - A failing row adds the cause (the `error_text` style, no secret).
  - `smtp` adds the P6 explanation when one matches.
- **Setup:** `Invoke-HealthCheck` runs the command (via `Invoke-ArciProcess`, `-P -m`), prints the
  table, and records the rows in the plan. A warn or fail makes the run end with code 1 (warnings);
  it is never a failure of the installation.
- **Inno finish page:** a line "Denetim: N tamam, M uyarı/eksik — ayrıntılar PowerShell
  penceresinde ve günlükte".
  - The line comes from a small result file the script writes (`install\selftest.json`).
  - The result file must not contain secrets; a test checks this.

### 2.4 P4 — Daily stamp-test limit

- **Config:** `TsaConfig.tests_per_day: int = Field(default=10, ge=0, le=20)`. It is browser-editable
  in section `tsa` without re-authentication (rules, contract, API shape, web field). Validation
  code `config_invalid`, as for the other numbers of the section.
- **API:** `admin_actions.tsa_test` uses
  `limit = min(config.tsa.tests_per_day, policy.tsa_test_per_day)`. The error stays
  `tsa_test_limit`.
- **New policy files** get `tsa_test_per_day = 20`:
  - `New-ArciAdminPolicy`, the `contract.AdminPolicy` default and the fallback all change;
  - an existing file is kept.
- **Web:** a number field "Günlük damga testi sayısı / Stamp tests per day" in step 7 beside the
  credit threshold, the step saved with "Kaydet" (the test step has no form).
  - Under the field: "Sunucu politikası en çok {{ceiling}} teste izin veriyor" when the ceiling is
    lower than the value.
  - The current "Günde en çok N test yapılabilir" shows the effective value.

### 2.5 P5 — Backup folder from the browser (C4)

- **Config:** `[backup] dir` moves from `security` (locked) to section `backup` (editable).
- **Rules for the value** (refusal codes `backup_dir_invalid` and `backup_dir_unsafe`). The folder
  must be:
  - an absolute path on a local fixed drive;
  - not under the program folder, the vault, `pgdata` or `C:\Windows`;
  - not a junction or symlink at any level that exists.
- **Apply:** the agent writes the change. ApplySystem (as SYSTEM) creates the folder and applies the
  backup folder's ACL entries from the ACL plan, then the change takes effect.
  - A failure leaves `[backup] dir` unchanged and reports `backup_dir_apply_failed`.
- **Listing:**
  - The backup list (C5) reads the current folder and lists the previous folder's sets with their
    folder.
  - The previous folder is remembered in `state\backup-dirs.json`, up to 5 entries.
  - Nothing is moved or deleted.
- **Tests:** FakeSystem plan tests and the Windows e2e (change the folder from the browser, run a
  backup, list both).

### 2.6 P6 — E-mail provider presets

- **Web: `web/src/pages/settings/smtp-presets.ts`.** It holds the preset table:

  | id | host | port | security | login | help key |
  |---|---|---|---|---|---|
  | `google` | `smtp.gmail.com` | 587 | starttls | user + app password | `smtp.presets.google` |
  | `google-relay` | `smtp-relay.gmail.com` | 587 | starttls | none | `smtp.presets.googleRelay` |
  | `microsoft365` | `smtp.office365.com` | 587 | starttls | user + password | `smtp.presets.microsoft365` |
  | `hosting` | (typed) | 587 | starttls | user + password | `smtp.presets.hosting` |
  | `company` | (typed) | 25 | none | none, or user + password | `smtp.presets.company` |
  | `other` | — | — | — | — | — |

  - The facts in this table are S3/S4.
  - Choosing a preset fills empty fields and asks before overwriting a filled one.
  - The preset is not stored: the page infers it from the host when it opens.
- **Help texts (TR/EN locale keys):** each one says what the provider needs, in 2–4 short lines.
  - **Google:** an app password after 2-Step Verification, where the administrator allows it; or
    the SMTP relay, whose settings in the Google Admin console authorise by the office's public IP.
  - **Microsoft 365:** SMTP AUTH must be enabled for the mailbox by the Microsoft 365
    administrator.
  - No link to a third-party page is embedded as a fetched resource. A plain URL text is allowed.
- **Core: `smtp.EXPLANATIONS`.** It maps a reply code and enhanced status (S5), together with the
  host family (Google `gmail.com` / `googlemail.com`, Microsoft `office365.com` / `outlook.com`),
  to `(tr, en)`.
  - `error_text()` keeps the raw reply.
  - A new `explain(exc, host) -> tuple[str, str] | None` gives the explanation.
  - The admin probe and the worker's alert-mail failure text show "<explanation> (<raw reply>)".
- **API:** the SMTP check result gets `hint_tr` and `hint_en` (nullable). The API contract and
  samples are regenerated.

- **AYARLAR.md / SETTINGS.md:** E-posta presets, the daily test limit, the backup folder.

## Deviations

### P6 (2026-11-08)

- **Sources read for S3–S5 (2026-11-08):**
  - Google Workspace Admin Help "SMTP errors and codes" (support.google.com/a/answer/3726730,
    updated 2026-10-26);
  - "Transition from less secure apps to OAuth" (answer/176600): username-and-password sign-in of
    Workspace accounts ended on 1 May 2025; `smtp.gmail.com` with an app password; the SMTP relay
    by IP;
  - "Route outgoing SMTP relay messages through Google" (answer/2956491): IP addresses and/or SMTP
    authentication, port 587 with TLS;
  - Google Account Help "Sign in with app passwords" (support.google.com/accounts/answer/185833):
    a 16-digit passcode, only with 2-Step Verification, `myaccount.google.com/apppasswords`;
  - Microsoft Learn "How to set up a multifunction device or application to send email using
    Microsoft 365" (updated 2026-10-05): `smtp.office365.com`, 587 (recommended) or 25 with
    STARTTLS, 465 not supported, Security defaults block basic authentication, 5.7.60 needs
    "Send As";
  - Microsoft Learn "Fix issues with printers, scanners, and LOB applications that send email
    using Microsoft 365" (2025-06-25): 5.7.3, 5.7.57, 5.7.139.
- **S5 status codes:** Google's page prints `5.7.80` and `5.7.90` where this contract had `5.7.8`
  and `5.7.9`. `explain` matches both forms (sahada doğrula: the first real refusal shows which one
  the servers send). The table also explains what the same pages list for this use: Google
  `5.7.14` and the relay's `5.7.0`/`5.7.1` refusals naming "relay"; Microsoft `5.7.57` and
  `5.7.60`. A Google `5.7.1` without "relay" (a policy or spam refusal) gets no explanation.
- **`explain(text, host)`** takes the error text as `error_text` writes it, not the exception: the
  probe's answer reaches the agent as text from its child process.
- **API:** the request error (`RequestError`, the agent's `ErrorRef`) carries the raw answer as
  `detail` (at most 300 characters, the probe's secrets removed) beside `hint_tr`/`hint_en`, for
  `smtp_test_failed` only: the explanation alone does not tell an unknown refusal apart. The
  worker's "Test e-postası gönder" result gets `hint_tr`/`hint_en` too. The alert e-mails' delivery
  rows (`last_error`) keep the raw reply only.
- **Help keys** are `settings.email.presets.help.<id>` (locale area `smtpPresets`), not
  `smtp.presets.*`, like the page's other texts.
- **Google Admin console path** is written with Google's English menu names (Apps → Google

### P3 (2026-11-08)

- **`secrets`:** only a store that does not open (no key file, a value the key cannot decrypt)
  fails. A missing credential of the time-stamp provider, the e-mail server or the replica is a
  `warn`: the browser's setup wizard asks for them after the installation, so a fresh
  installation would otherwise always fail. `database.password` is not required (a local trust or
  SSPI setup has none).
- **`database`** runs `arcilogger-db --config <toml> check` as a child process with the same
  interpreter (`-P -m arcilogger_db`): core imports no database code (ADR-0001,
  `core/tests/test_independence.py`). An installation without the database package skips the row.
  Warnings of `check` that are not about the schema (partitions, telemetry) keep the row ok.
- **`roots`:** the mock provider is skipped. Its test root is made on its first stamp; asking for
  it would write it, and the self-test writes nothing.
- **`clock`:** the time servers are asked directly over SNTP. `check_clock` would write a clock
  sample and raise R20-clock; the self-test writes nothing.
- **`tsa.reach` for TÜRKTRUST** sends a GET without credentials through the configured proxy; any
  HTTP status counts as reached (401 is the expected one).
- **The SMTP test** uses the existing plain SMTP stub with `AUTH PLAIN` (core's `SmtpTestServer`
  has no STARTTLS). `SmtpSender.check()` shares the connection code (`_open`) with `send()`.
- **The result file** `install\selftest.json` is `{ok, warn, fail, skip, rows}`, counts first:
  Setup's finish page reads the counts from the top of the file. A row keeps only its id, status
  and texts. The run removes the file of an earlier run before it starts.

### P2 (2026-11-08)

- **The example keeps the Kamu SM lines as a commented block** under the TÜRKTRUST lines.
  `-TimeStampProvider zamane` removes the two TÜRKTRUST lines and turns those six lines on
  (`Set-ArciExampleTsaProvider`), so today's Kamu SM keys live in one file, not in the script.
- **Kuruluş adı on the page:** at most 200 characters, the rule of the installer and of core
  (§2.2 said 2–120). Refused on the page as well: a double quote, a control character, a leading
  `-` and a trailing `\`, so the value is always one quoted argument.
- **Saat sunucusu on the page:** a host name or an IPv4 address (letters, digits, `-`, `.`). The
  script still accepts an IPv6 address given on its command line.
- **Yönetici adresi:** the page passes one comma-separated argument. The script now splits
  `-AdminAddress` values at commas, semicolons and spaces, as its console prompt does.
- **Code 2 of a first installation:** Setup cannot tell which preflight check failed, so its
  dialog names the three page values and points at the `[HATA]` line in the PowerShell window.
- **`-TimeStampProvider` with an existing configuration** is a preflight warning ("not applied")
  and changes nothing; an upgrade's Setup never passes it.
- **Next steps:** a configuration that cannot be read follows `-TimeStampProvider` (TÜRKTRUST by
  default); only Kamu SM gets the Kamu SM text.
- **Web:** TÜRKTRUST's servers come first for every site not on Kamu SM (the mock, another RFC
  3161 server, TÜRKTRUST itself); a Kamu SM site keeps its order. The target of a mock site's
  save without a chosen server stays the Kamu SM test server, as the page says.
